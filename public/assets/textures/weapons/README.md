# Weapon Skins

Drop-in texture files for weapons. The client auto-loads these at startup —
no code changes needed.

## Where to drop files

- **`public/staging/textures/weapons/`** — pending / under evaluation
  (gitignored, still web-served; never committed)
- **`public/assets/textures/weapons/`** — accepted & committed running skins

Acceptance is a plain file move:
`mv public/staging/textures/weapons/<file> public/assets/textures/weapons/<file>`
then `git add` (no `-f` needed). Note: this system is currently dormant
(`weaponskins.ts` is not imported by the live weapon renderer, which uses the
procedural PBR texture sets).

## Files

| File | Purpose |
|------|---------|
| `{weaponId}.png` | Albedo / color skin (512x512 recommended, seamless tiling recommended) |
| `{weaponId}_bump.png` | Optional grayscale bump map (mid-gray 128 = flat) |
| `skins.json` | Optional manifest listing which skins exist (avoids 404 probing) |

## Weapon IDs

`knife`, `glock`, `usp`, `deagle`, `mp5`, `ak47`, `m4`, `awp`, `c4`

## How it works

- The skin replaces the procedural albedo texture on the weapon's main
  surfaces (metal, wood, polymer, magazine, slide, suppressor, c4 body).
- Hands, sights, lenses, LEDs and sleeves keep their procedural look.
- Pattern density scales with part size (about one tile per 22 cm).
- Applies to the first-person viewmodel, other players' world guns and the
  planted bomb (for `c4`).
- Delete a PNG (and its entry in `skins.json`) to fall back to the built-in
  procedural texture.
- If `skins.json` is absent, the client probes all weapon IDs by URL.

## Bundled demo skins (original artwork, generated by scripts/gen_weapon_skins.py)

- `ak47` — "Jungle Digital" camo (+ matching bump map)
- `awp` — "Arctic Splinter"
- `deagle` — "Carbon Blaze"

## Note

Only add artwork you have the rights to use (your own, CC0, or properly
licensed). The bundled files are generated programmatically and are free of
third-party game assets.
